## 3. Server and security

Overall sound: constant-time password check, fails closed, malformed auth → 401, CSRF checks on upload, path traversal blocked, no secrets in the bundle, **no real data ever committed** (full history checked).

| # | Finding | Severity | Confidence |
|---|---|---|---|
| 3.1 | **Concurrent uploads race**: shared temp filename; current file moved aside before the new one is written. Reproduced: 500s, a 200 that stored another request's data, GETs returning "nothing uploaded", lost versions. Realistic via double-click or two devices. | medium | high |
| 3.2 | No rate limit/lockout or logging of failed logins. Cheapest fix: random 20+ character password. | low-medium | high |
| 3.3 | Full snapshot cached in each browser's localStorage indefinitely (shared computer risk); no "forget this device". | low | high |
| 3.4 | Built assets sent `Cache-Control: public` behind auth → should be `private`. No CSP / HSTS headers. | low | high |
| 3.5 | Unauthenticated malformed request lines (and `Origin: null`, bad `%` encoding) give 500s with stack traces in logs; corrupt-file errors may log data fragments. | low | high |
